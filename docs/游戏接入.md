# 快速开始 — 把 NPC 大脑接进你的游戏

NPCSidekick 对游戏暴露 **3 个 HTTP 端点**。游戏端只需要能做 HTTP 请求（Godot 的 `HTTPRequest`、Unity 的 `UnityWebRequest`、任何语言的 fetch 都可以）。

> ⚠️ **口径补充（2026-09-15）**：这 3 条是**最小接入面**（纯对话 + 镜像 + 派活）。
> 若走**协议 v1**（mod 作为自主消费者认领并执行任务），还要加两条：
> `POST /api/consumer/hello`（报到 + 能力协商）与 `POST /api/task_done`（销账）——
> 见 `engine-clients/common/PROTOCOL.md`。**全量端点（40 条）**见 `docs/API.md` §9。

## 1. 启动大脑

```bash
pip install -e .        # 尚未发布 PyPI：先 git clone 本仓库再本地安装（见 README「快速开始」）
python -m npc.server --adapter paleolithic --no-browser
# 服务器监听 http://127.0.0.1:8765
```

- `--adapter paleolithic`：加载旧石器演示村民（苍 / 阿黎）
- `--persona-dir <目录>`：从自己的 JSON 目录加载角色（放文件即用）
- 不传 LLM key 也能跑——对话自动退化为规则话术，日常行动完全不受影响

## 2. 端点契约

### `POST /api/talk` — 玩家对话（含指令）

请求：
```json
{"npc_id": "cang", "message": "给我两根木材"}
```

响应：
```json
{"reply": "好，我这就去弄2个木材给你。"}
```

对话里带指令（"给我N个X"）时，NPC 会**真的去执行**：接单 → 走进度 → 完成后通过 `delivered` 计数反映在状态里。资源不足会诚实拒绝。

### `GET /api/state` — 世界状态（游戏镜像用）

```json
{
  "actors": {
    "cang": {"position": "村庄", "inventory": {"木材": 1}, "state": "working", "activity": "采集木材×2（剩 3 步）"}
  },
  "delivered": {"木材": 1173},
  "tick": 24036,
  "log_tail": ["cang 说: 柴火要挑干透的。", "cang 将 木材 交给了 主角"]
}
```

- `state`：`idle` / `walking` / `working` / `resting` — 游戏按它表演走路/干活/休息
- `activity`：当前进行中的日常描述
- `log_tail`：最近事件（游戏差分显示气泡）
- `delivered`：各资源累计交付数（**游戏侧按增量触发交付动画**，别按 log 文本去重）

### `POST /api/task` — 直接派活（跳过对话）

```json
{"npc_id": "cang", "resource": "木材", "count": 2}
```

## 3. Godot 接入模式（参考实现）

游戏项目里的 `scripts/npc/Villager.gd` 是一个完整参考：

1. **轮询镜像**：每 2 秒 `GET /api/state`，把自己角色的 `position/state/inventory` 存下来
2. **表演**：`walking` → 走向对应地点锚点；`working` → 播放干活动画；`resting` → 站立
3. **交付**：`delivered` 计数增量 → 触发递交动画 → 物资进玩家背包或营地仓库
4. **气泡**：`log_tail` 里 `"<id> 说: "` 开头的新行 → 头顶气泡
5. **自动拉起**：游戏 `_ready` 时健康检查，服务器没起就 `OS.create_process` 拉一个（隐藏窗口）

要点：
- **别用 log 文本做交付去重**（同文本行会重复出现）——用 `delivered` 计数增量
- 村民动画与大脑状态解耦：大脑只管"谁在哪、在干什么"，动作细节全是游戏侧表演
- 对话框关闭时机：玩家发过话 → 回复打字机打完 → 停 0.3 秒 → 村民动身时自动关
