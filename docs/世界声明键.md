# 世界声明键总表

世界状态是一个**纯 JSON dict**（可序列化 / 可编辑 / 可存档）。本表穷举**下划线开头的
扩展声明字段** —— 它们是游戏制作者告诉大脑"我的世界长什么样"的通道。

- 参考实现请看 `npc/world.py` 的 `default_world()`（也是本表各键的示例值来源）
- 老存档缺键时的迁移清单见 `npc/server.py` 的 `_MIGRATED_DECL_KEYS`
- 改完世界 JSON 不需要改任何 Python 代码

---

## 一、最重要的一条：兜底三态

**声明字段没写的时候，大脑按三态处理** —— 这是"别人拿这个引擎接自己的游戏"能成立的唯一前提：

| 状态 | 判定 | 行为 |
|---|---|---|
| ① 世界已声明 | 键存在且值合法 | **用声明值** |
| ② 世界已加载但未声明 | 世界加载了，该键缺失 | **中性 / 空** —— 制作者的沉默 = 不要我的内容 |
| ③ 未加载任何世界 | 引擎裸调用 / 测试复位态 | **参考默认**（保向后兼容） |

**态②是关键。** 没有它，"可覆盖"就是假的：你的游戏只要漏声明一个键，就会从兜底里
继承本参考世界的资源名、地名、台词 —— 污染你的检索与对白。

反面例子（已修）：资源词典曾经写成 `active if active else None`，把"已加载但为空"和
"未加载"压成同一个值，于是纯对话游戏会继承「木材/浆果/石头」—— 三态退化成两态。

## 二、声明字段总表

### 2.1 世界结构 / 界面

| 键 | 类型 | 语义 | 未声明时 |
|---|---|---|---|
| `craft_at` | `str` | 制作台所在地点 | `None` = **就地可制作** |
| `_default_spawn` | `str` | 新角色槽的出生点 | 取 `locations` 的第一个地点 |
| `_hud.panels` | `[str]` | 游戏该显示哪些状态面板 | **全部面板**（存量世界零回归） |

### 2.2 世界推进

| 键 | 类型 | 语义 | 未声明时 |
|---|---|---|---|
| `_autonomy` | `"free"` \| `"game"` | 大脑与世界推进的耦合关系： <br> `game` = 尊重游戏端，**没有活跃客户端时不推进世界**（mod 退出则大脑停推，省 token）；`free` = 大脑自己推 | **`"free"`** |

> ⚠️ 游戏端接入时建议显式声明 `_autonomy`。不声明就没有"没人在场就停推"的省 token 行为。

### 2.3 资源经济

| 键 | 类型 | 语义 | 未声明时 |
|---|---|---|---|
| `_resource_caps` | `{资源: int}` | 资源回补的**上限** | `999`（旧记忆卡缺失时兜底） |
| `_resource_regen` | `int` | 每 tick 向 `_resource_caps` **回补多少** | **`0` = 不回补**（资源会真的采空） |
| `_resource_aliases` | `{规范名: [别名]}` | 接单 / 检索用的资源同义词 | 无别名（每条只剩规范名自身） |

> ⚠️ **参考世界必须声明 `_resource_aliases`**。不声明则加载世界后每条只剩规范名自身，
> "砍柴 / 木头" 这类同义说法全部接不住（而测试默认跑在"未加载世界"态，走含同义词的
> 硬编码默认表，恒绿看不见 —— 这个坑曾经长期存在）。

### 2.4 检索召回

| 键 | 类型 | 语义 | 未声明时 |
|---|---|---|---|
| `_entity_synonyms` | `{规范名: [别名]}` | 记忆召回用的词表（同义归一） | **空表** = 无同义召回，只有分词原词匹配 |
| `_entity_single_chars` | `[str]` | 允许参与子串匹配的**单字**白名单 | 空表（单字一律不参与，防"大家/了不起"里的"家/木"误命中） |

### 2.5 文案 / 对白

| 键 | 类型 | 语义 | 未声明时 |
|---|---|---|---|
| `_weather_text` | `{天气值: 文案}` | `observe()` 注入的天气描述句 | 不追加天气描述行 |
| `_review_tpl` | `{disallowed, forbidden, exhausted}` | 审查拒绝语模板，占位符 `{action}` / `{resource}` | **引擎中性默认**（不含任何游戏词） |
| `_place_aliases` | `{规范地名: [别名]}` | 地点词典（goto 接单时最长匹配归一） | 无别名 |

引擎中性默认（未声明 `_review_tpl` 时）：

| 键 | 引擎中性默认 |
|---|---|
| `disallowed` | `……这个我不会做（不允许的动作：{action}）。` |
| `forbidden` | `……这个涉及我不该碰的东西。` |
| `exhausted` | `……{resource}现在弄不到了。` |

> 注意：中性默认**不含"资源会长回来"这类假设** —— 那是世界的事，不是引擎的事。
> 参考世界因为声明了 `_resource_regen`，所以它自己的措辞可以提"等它长回来吧"。

### 2.6 运行时写入的键（不是制作者声明的）

`_tick`（帧计数）｜`_weather` / `_game_hour` / `_player_pos` / `_context_at`（游戏端经
`/api/talk` 的 `context` 同步进来）｜`_log_offset` / `_prev_hour`（日志轮转与昼夜边界）。

## 三、契约字段（非下划线，属世界语义本体）

| 键 | 语义 |
|---|---|
| `locations` | `{地点名: {desc, resources{资源: 余量}, exits[]}}` —— 地点图、资源分布、可达性 |
| `actors` | `{npc_id: {position, inventory, stamina}}` —— NPC 角色槽 |
| `protagonist` | `{position, name}` —— 主角位置（交付判定用） |
| `delivered` | `{资源: 数量}` —— 已交付给主角的物资 |
| `recipes` | `{配方名: {材料: 数量, produces: 产物}}` |
| `log` | 世界事件日志（append-only，超过阈值自动搬冷层归档） |

## 四、加一个新声明键要做什么

1. 在 `npc/world.py` 加一个**读取函数**，风格照 `autonomy_mode()` / `craft_station()` /
   `regen_rate()`：模块级纯函数、`world.get` 读单个键、类型与合法性校验、
   非法或未声明显式回落到**引擎中性默认**，docstring 里写明三态。
2. 在 `default_world()` 里给出参考世界的声明值（值与旧行为等价则零回归）。
3. 在世界就绪的注入点（`npc/bootstrap.py`）调用加载器。
4. 若老存档会受影响，把键名加进 `npc/server.py` 的 `_MIGRATED_DECL_KEYS`。
5. **补三条锚测试**：未声明时行为 / 声明后生效 / 参考世界声明与旧行为等价。
   ⚠️ 至少要有"加载真实世界后"的那一条 —— 否则漏声明会像以前一样被测试态掩盖。
6. 回过头更新本表。
