# 任务书 #02：任务回路最小闭环（follow_player / goto）

> 主控：李胜（NPCSidekick 项目）｜执行：Trae 或等价强模型｜验收：主控
> 本次任务跑在 **D:\NPCSidekick\1_Dagent**（大脑仓库）。

## 1. 背景

架构文档 §10"任务回路"未开工（最初诉求的最后一块）。
现状：NPC 会接单落账（B2 编译→book → dispatch），GTA 适配器已上线，但
协议 v1 只覆盖了资源类动作（gather/craft/deliver/move）。缺"跟随玩家、去某地"类
**需要与游戏端移动联动**的任务动作——玩家对 NPC 说"跟着我/陪我去河边"时，
NPC 会答应（B1 承诺 + 落账），但游戏端没有执行回路。

## 2. 目标

最小闭环：`玩家说"跟我走" → B2 编译任务(follow_player) → dispatch → 游戏端执行
（GTA ped 跟随玩家移动）→ POST /api/task_done 回传 → 世界日志/记忆落事件`。

## 3. 验收标准（全过才算完）

1. 动作清单 manifest 新增 `follow_player`（tier=3, approval=ask, params=[]）、
   `goto`（tier=2, approval=ask, params=["地点"]），默认清单不变（向后兼容）
2. B2 编译：`npc/reviewer.py` 词表认出"跟我走/跟着我/陪我去X/到X去"→
   `{"action": "follow_player"}` / `{"action": "goto", "params": {"地点": "河边"}}`
3. `/api/task` 下发后 mod 侧 TaskExecutor 认领：ped 跟随玩家/前往地点（GTA mod
   NPCSidekickGTA.cs 已有 ped 控制代码段可复用）；执行过程世界日志可见
4. 完成后 `POST /api/task_done` → 事件落账（EV_DONE 记忆 + /api/events deliver 类事件）
5. 玩家中途走远/任务超时 → taskloop 既有超时回收路径生效（不新增回收到）
6. 新增测试：B2 词表→任务编译 3 例 + 协议 v1 dispatch→done 2 例 + manifest 加载 2 例；
   全量不小于 **748 passed**
7. 文档：NPC大脑架构.md §10 从"未开工"改"已实施" + 更新 PROTOCOL.md 动作表

## 4. 技术要点（已探明，别走弯路）

- 大脑动作白名单在 **manifest**（`reviewer.py::load_manifest`，默认清单在代码兜底）；
  GTA 适配器有 `npc/adapters/gta.py` + `npc/personas/gta/`（麦克家三人的核心场景）
- 协议：`engine-clients/common/PROTOCOL.md` v1 —— `/api/task`（booked→dispatched
  首派标记）、`/api/task_done`、`EV_DONE`/`EV_FAIL` 前缀（`npc/memory.py` 常量）
- B2 编译走 `npc/subagent.py` + `NPC_SUBAGENT_B2` 开关（启动 bat 已开）；词表兜底在
  `reviewer.py`（LLM 编译失败时规则识别——跟"给我两根木材"同一套词表，加同款词）
- **别动**：调度队列（§19）、安检门（§25）、`world.py` 日志格式（游戏端解析依赖）
- 已知边界（可留 TODO）：craft 类任务经对话仍不可接（resource 可行性检查不认 recipe）
