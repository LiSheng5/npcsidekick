## 1. 为什么用本地模型

| | 云端 API（DeepSeek） | 本地模型（Ollama 等） |
|---|---|---|
| 成本 | 按 token 计费（对话还好，决策层高频就贵） | **免费** |
| 延迟 | 1-10 秒 | **<1 秒**（显卡够时） |
| 离线 | 需要网络 | **断网可用** |
| 能力 | 强 :（V4 系列）等 | 弱一档（7B 级 ≈ 几年前云端水平） |
| 适合 | 对话（要聪明） | **高频决策、日常话术、导演层派活** |

## 2. 推荐方案：Ollama（最简单）

```bash
# 1. 安装 Ollama（ollama.com）并拉模型
ollama pull qwen2.5:3b        # 对话：3B 够用（中文不错）
ollama pull qwen2.5:7b        # 决策/导演层：7B 更好

# 2. 启动（默认 11434 端口）
ollama serve
```

Ollama 提供 **OpenAI 兼容端点**：`http://127.0.0.1:11434/v1`。

## 3. 接入方式（环境变量）

NPCSidekick 的 provider 工厂（`agent/providers/factory.py`）按模型名自动路由 base_url。接本地：

```bash
# Linux/macOS
export DEEPSEEK_BASE_URL="http://127.0.0.1:11434/v1"
export DEEPSEEK_API_KEY="ollama"          # 本地不需要真 key,占位即可

# Windows PowerShell
$env:DEEPSEEK_BASE_URL = "http://127.0.0.1:11434/v1"
$env:DEEPSEEK_API_KEY = "ollama"
```

## 5.导演层 + 本地模型配套

| 层 | 模型 | 频率 | 说明 |
|---|---|---|---|
| 普通 NPC 日常 | **无 LLM**（规则 routine） | 每 3s × NPC 数 | 零成本 |
| 普通 NPC 对话 | 本地 3B（或云端 flash） | 玩家触发 | 便宜 |
| **导演层（v4）** | 本地 7B-14B | 每 5-10s × 1 | 全游戏一个大脑，派活给 NPC |
| v4 帮手 NPC | 本地 7B+ | 任务触发 | 完整 agent 循环 |

## 6. 常见问题

- **模型跑不起来？** 检查显卡显存：3B ≈ 3-4GB，7B ≈ 6-8GB（量化后更低）。没显卡 CPU 也能跑，慢一些
- **Ollama 报 404？** 模型没拉：`ollama list` 确认，`ollama pull <名字>`
- **接上后对话没变化？** 确认 `GET /api/mode` 返回 `"mode": "llm"`；看服务器日志有没有 provider 报错
- **中文乱？** qwen2.5 系列中文好；llama 系中文一般，换 `qwen2.5` / `glm4` 系
