## 1. 背景

记忆系统 review（2026-08-28 完成）发现的三个 P1 项，均集中在 `npc/memory.py`：

- **A 分词三遍**：`retrieve()` 在 `NPC_BM25_RECALL=1` 时对同一批记忆重复
  `_tokenize()`（jieba）三次（q_tokens 一次、df 统计一次、逐条打分一次）——
  几百条记忆 × jieba 慢速 = 每轮对话多几十~几百 ms 纯浪费
- **B BM25 名实**：`_idf_relevance()` 实为 **IDF 加权重合度**（无 tf 分量、无 k1/b 参数，
  entry 还被 `set()` 去重），但提交信息/文档都写"BM25-IDF"——借了 TDAM
  （TencentDB-Agent-Memory）的检索技术名，实现了简化版
- **C 测试硬伤**：`tests/test_bm25_recall.py` 全是 ASCII 空格词语料（中文主场景零覆盖）；
  `tests/test_npc_persona.py` 的 `_PersonaLLM.calls` **类级共享且不清理**（改变用例顺序
  或 `-k` 单跑互相污染）

## 2. 目标与验收

- 验收：`tests/test_memory_tokenize.py` 或新增用例断言**行为不变**（开关开/关排序、
  top_k 结果与改前逐字节一致）；跑通即可，不要求性能基准图（但可在文末附改善量）

### B BM25 名实（选型已定）
- **执行真 BM25 + RRF**（对齐 TDAM，推荐）：`_idf_relevance()` 原地升级为 BM25 公式
  （保留 entry 词频不做 set 去重，`k1=1.2, b=0.75`），开关名 `NPC_BM25_RECALL` 不变；
  与温层向量锚点（`NPC_VECTOR_ANCHOR`）的融合从 `max(旧, IDF)` / `+2.0×score` 线性加分
  改为 **RRF（倒数秩融合 `1/(k+rank)`，k=60）**，可让 IDF 路与向量路排名融合
- 验收：旧用例 `test_bm25_recall.py`（稀有词胜出/开关关回归锚）保持意义可过——开关关
  **必须与旧版排序一致**（回归锚 B1 铁律）；新增中文用例（"矿洞/石头"含 jieba 路径）
  至少 2 例；RRF 替换后向量锚点组合路径至少 1 例
- **如果执行中真 BM25 实现遇阻**：退一步只做"改名 `_idf_overlap` + 文档措辞修正"
