# 跨引擎适配（Unity / Unreal / 通用）

> 最后更新：2026-08-21。
> 核心结论：**NPCSidekick 大脑本体已经跨引擎**——它只暴露 HTTP 端点，任何引擎用任意 HTTP 库都能接。
> 本文给出各引擎的"客户端样板"（把游戏画面/角色表演接上大脑），参考实现是 Godot 的 `scripts/npc/Villager.gd`（轮询镜像 + 表演 + 交付 + 气泡）。

## 1. 为什么大脑天然跨引擎

大脑暴露 3 个纯 HTTP 端点，无任何引擎依赖：

| 端点 | 用途 | 任何引擎都能调 |
|---|---|---|
| `POST /api/talk` | 对话（带 `voice:true` 返回语音） | `UnityWebRequest` / `HttpClient` / `fetch` |
| `GET /api/state` | 世界状态镜像（轮询表演） | 同上 |
| `POST /api/task` | 直接派活 | 同上 |

返回纯 JSON（+ 可选 base64 mp3），不绑定 Godot/Unity/Unreal 任何 API。

## 2. 各引擎客户端样板

每个引擎需要一个 `NpcBrain` 客户端，做这 5 件事（Godot 参考实现已验证）：

1. **对话**：POST `/api/talk`（`npc_id` + `message`，可选 `voice:true`）
2. **轮询镜像**：定时 GET `/api/state`，存下角色的 `position/state/inventory`
3. **表演**：`walking`→走向锚点；`working`→播放干活动画；`resting`→站立
4. **交付**：`delivered` 计数增量 → 触发物品进背包/仓库
5. **气泡**：`log_tail` 里 `"<id> 说: "` 的新行 → 头顶气泡

对应示例文件（本仓库 `engine-clients/`）：
- `godot/NpcBrain.gd` — Godot 参考（`docs/游戏接入.md` §3 也有内联骨架）
- `unity/NpcBrain.cs` — Unity（`UnityWebRequest`）
- `unreal/NpcBrain.h/.cpp` — Unreal（FHttpModule）
- `common/` — 通用 fetch / Python 示例

## 3. 关键契约（各引擎实现时保持一致）

- **交付去重**：别用 `log_tail` 文本去重（同文本行会重复），用 `delivered` **计数增量**触发动画
- **动画与大脑解耦**：大脑只管"谁在哪、在干什么"，动作细节全是引擎侧表演
- **权威状态在引擎侧**：大脑的建议（想去哪/想干什么）由引擎校验后执行，大脑只提议不直接改世界
- **语音**：`/api/talk` 带 `voice:true` → 响应含 `audio`（base64 mp3），引擎解码播放；无 audio → 纯文本保底
- **本地绑定**：服务器默认只绑 `127.0.0.1` —— 同机没问题；跨机/打包需放开绑定 + 加 token

## 4. 机器人版的复用点

相同的"大脑 + 落账口 + 记忆 + 防篡改"可直接复用到机器人：客户端换成 ROS2 action / 厂商 SDK（如宇树），
把 `/api/task` 返回的动作序列翻译成关节轨迹/运动指令即可。见 `docs/NPC大脑架构.md`。

## 5. 未来：引擎 SDK 化

若要让零代码制作者也能接（类似 AI Character Engine 的 GamePlugin），可渐进：
1. 包一层引擎插件（Unity Package / UMG 组件）
2. 暴露少量绑定（角色 id、服务器地址、show bubble / play anim 回调）
3. 制作者只填配置，不写代码
—— 但这是后续迭代，当前先交付"样板可抄"。
