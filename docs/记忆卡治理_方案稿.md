## 二、病根链（三层放大）

1. **源头无闸**：`npc/scheduler.py:251/272` 自主日常循环每次完成任务就
   `npc.remember(f"完成：{desc}", importance=5)` ——挂机休息=无限刷屏。
   （另：npc.py:395 玩家任务完成写 `完成: {task}` 半角冒号 imp=8，格式都不统一）
2. **反思被劫持**：反思阈值=未反思条 importance 和 ≥12。垃圾条 imp=5，
   **每攒 3 条垃圾就触发一次反思**，把 8 条"休息2刻"喂给 LLM 总结出
   "我为什么一直在休息"的废话洞察，再以 **imp=8、category=reflection** 写回——
   而 imp≥8 与 reflection 是遗忘机制的**重点保护对象**，永远剪不掉。
3. **合并机制失明**：`consolidate()` 的主题分组靠 `_ENTITY_SYNONYMS`
   （只有木材/浆果/石头等旧石器资源词），"休息"不在表里 → 规范词交集为空
   → 永远进不了合并组；弱枝修剪要等强度 <1（72h 半衰期需 ~7 天进程时间），远水不解近渴。

## 三、方案总览：两道闸 + 一次迁移

原三件套口径的落地映射（A 已退役，由**确定性脚本**接棒——更符合"LLM 只提议、代码决定执行"）：

| 原口径 | 本方案落地 |
|---|---|
| B 过滤写入 | **闸1 写入去重聚合** + **闸2 反思卫生**（纯规则，0 LLM，0 token） |
| A 一次性拆卡迁移 | **迁移工具** `scripts/migrate_memory_cards.py`（备份→清洗→重建，跑一次即止） |
| 反思压缩洞察卡 | 已有管线保留（阈值12/批8/每tick检查），仅加卫生条款 |

### 闸1 写入去重聚合（改 `NPC.remember()`，所有写入路径的唯一咽喉）

- 新记忆与卡内**既有条目完全同文**且 `category=general` 且 `importance≤6` 时：
  不新增条目，改为**就地更新**那条（刷新 `created_at`、累加 `count` 字段）。
  检索时它自然因新鲜度浮起，但只占一个坑。
- `importance≥7` 的（玩家任务完成、接任务）**永不合并**——正事每次都记。
- 效果：休息循环从"3500 条"变"1 条（count=3527）"；反思输入的 importance 和
  也随之失血，不再被垃圾触发。

### 闸2 反思卫生（改 `maybe_reflect()`，防"总结垃圾产生垃圾"）

- 候选批内**唯一内容数 <3** → 判定为日常噪音：推进 `_reflected_upto`
  （标记已归纳），**不调 LLM、不写反思**，静默翻篇。
- 反思产出与最近既有 reflection 条目重复 → 丢弃不写。

### 迁移工具 `scripts/migrate_memory_cards.py`（一次性，手动运行）

流程：`备份 → 清洗 → 重建 → 报告`，**默认 dry-run 只出报告，`--apply` 才落盘**；
落盘走 tmp+rename 原子写；二次运行幂等（0 改动）。

清洗规则（按序）：
- **R1 全卡精确去重**：同 `(content, category)` 只留最新一条（先止血再动刀）
- **R2 流水账清除**：`category=general 且 importance≤5 且 content 匹配 ^完成：`（全角冒号=scheduler 签名）→ 删除。
  玩家正事（半角冒号 imp=6/8）分毫不动——确定性规则，零误伤
- **R3 退化反思处置**（默认档）：删除内容中提及休息循环的反思条
  （命中 `/休息/` 即删）；备选激进档：家人卡 reflection 全弃
- R4 重建 `reflected_upto = len(entries)`，保存

预期效果（dry-run 可验证）：家人卡 3863→约 10~30 条干净起步，
cang 522→约 90 条；检索池瞬间恢复信噪比。
