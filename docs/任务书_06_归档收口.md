## 1. 背景

管家把流水账降级 `general→archived`（退出检索上下文、永不物理删除），
但 archived 条目**仍参与**两处零 LLM/LLM 流程：

- `npc/memory_card.py::maybe_reflect` 的候选批（L186-188）不过滤 archived
  → 已降级的流水账可能被反思重新归纳成 reflection，**重新进入 LLM 上下文**
- `npc/memory.py::consolidate` 的分组/修剪（L349-365）不过滤 archived
  → 已降级的条目被同主题合并卷走或参与修剪，破坏"证据链在卡上"的契约

结果：降级语义只覆盖了检索/上下文两条消费路径，反思与合并两条漏了——
archived 内容能"借尸还魂"。

## 2. 目标与验收

1. **反思候选排除**：`maybe_reflect` 的 `entries` 过滤
   `e.get("category") != CATEGORY_ARCHIVED`（memory.py 已导出该常量，
   `from npc.memory import CATEGORY_ARCHIVED`）——archived 不再成为反思素材，
   也不推进反思指针的计数口径（推进逻辑跟着过滤后的批走，别只滤不推）
2. **合并/修剪排除**：`consolidate` 的同主题分组（`_canonical_terms` 分组键）
   与弱旧修剪候选都排除 archived——archived 不被合并、不被修剪、不被触碰
3. **归档永存**：archived 条目物理留在卡文件里（红线不变）；`retrieve()` /
   `format_for_context()` 的 `active()` 口径不变（已单点）
4. 新增测试 ≥4 例：反思候选跳过 archived / 反思指针随过滤批推进 /
   consolidate 不合并不修剪 archived / 降级后反思+consolidate 一轮跑 archived
   纹丝不动；全量 ≥ **777 passed**
5. 文档：NPC大脑架构.md §27 补一句归档语义收口
