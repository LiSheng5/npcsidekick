## 四、协议面设计

### 4.1 方言清单 `npc/adapters/<game>/actions.json`

Schema **完全沿用** examples/actions.json（tier/approval/params/desc），仅顶层加 `"schema_version": 1`。
GTA 首批六动词（已落盘 `npc/adapters/gta_actions.json`）：
follow_player(持续型) / goto / enter_car_with_player / drive_to / wander(持续型) / say。

纪律：此文件与适配器同居，npc.py 核心依旧零引擎字样；地点参数走别名表或
context.player_pos 的字符串地名约定。GTA bat 以 `--manifest npc/adapters/gta_actions.json` 装载。

### 4.2 能力协商（消费者 hello）

- `POST /api/consumer/hello {"name","version","verbs"[]}` → 内存消费者表；
  mod 每 ≤30s 重发即心跳（`NPC_CONSUMER_TTL` 默认 60s 判死），state 轮询可带
  `?consumer=<name>` 触碰心跳。
- B2 白名单 = `manifest.actions ∩ ∪活跃消费者.verbs`；空集 → Task 类拒绝编译，
  NPC 诚实回话——事前防空承诺门。

### 4.3 账本 GoalData 状态机

```
字段: task_id("t_<seq>") · npc_id · chain_id · action · params{} · desc ·
      state · error · created_at · dispatched_at · done_at
状态: booked → dispatched → completed | failed | cancelled(superseded/chain_failed)
```

- **booked**：B2 编译落账（book() 镜像，旧 pending_task 字段保留兼容）。
- **dispatched**：`/api/state` 响应挂 `pending_tasks[]` 首次下发时标记。
- **回报**：`POST /api/task_done {"task_id","status":"completed"|"failed","detail"}`
  → 销账 + 记忆卡（完成 imp=8 / 失败 imp=6）+ 失败时 say 字幕商议推送。
- **僵尸账**：dispatched 超 `NPC_TASK_TIMEOUT`（默认 300s）→ failed(timeout) 进商议；
  tick 循环每帧回收。
- **链式**：同 chain_id 按 book 顺序派发，前节 completed 才派下一节；
  失败 → 整链剩余节点 cancelled(chain_failed)，商议只记失败源一次。
- **持续型动词**：dispatched 即在岗；同 NPC 新落账自动 superseded 旧行。
- **出站核对后继**：承诺↔账本一致性由既有 review_dialogue 兜住（架构现成），
  泛化版列 M2+。
