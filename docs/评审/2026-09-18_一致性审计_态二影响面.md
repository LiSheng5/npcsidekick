## 一、态② 影响面（实测，非推测）

### 1.1 现状实现

```python
# npc/reviewer.py
44: _ACTIVE_RESOURCE_ALIASES: Optional[Dict[str, tuple]] = None
93:     _ACTIVE_RESOURCE_ALIASES = active if active else None      # ← 病灶
94:     return dict(_ACTIVE_RESOURCE_ALIASES or DEFAULT_RESOURCE_ALIASES)
99:     return _ACTIVE_RESOURCE_ALIASES if _ACTIVE_RESOURCE_ALIASES else dict(DEFAULT_RESOURCE_ALIASES)
```

`active if active else None` 把**空表**和**未加载**压成同一个值 —— 三态退化成两态。

### 1.2 实测三态对照（我实跑的结果）

| 状态 | `get_resource_aliases()` | `compile_task("去帮我砍点柴")` | `compile_task("给我两根木材")` |
|---|---|---|---|
| ③ 未加载世界（测试默认态） | `['木材','浆果','石头']`（硬编码默认表） | ✅ 认得 → 木材 | ✅ |
| ① 加载参考世界（**= bootstrap 生产路径**） | `{'木材':['木材'], '石头':['石头'], '浆果':['浆果']}` | **❌ 返回 None（不认得！）** | ✅ |
| ② 加载零资源世界（纯对话游戏） | `['木材','浆果','石头']` | ✅ | **✅ ← 别的游戏继承了本游戏词表** |

### 1.3 缺陷 A：态② 泄漏（你最初担心的那件事）

> 纯对话世界（一个资源都没有）→ 词典回退到硬编码的「木材/浆果/石头」→ **"给我两根木材" 照样编译成任务**。

即：**别的游戏只要漏声明资源，就会继承本游戏的资源词表**。与"兜底三态"相悖。

⚠️ **但这是被文档明确写为契约的行为**，不是疏忽：

```python
# npc/reviewer.py:59-62 docstring
#   收集到 ≥1 个资源 → 整表替换默认（游戏声明自己的真相, 不让别游戏的残留词漏进来）;
#   纯对话世界(一个资源都没有)→ 回退默认表;      ← 明确声明这就是设计意图
```

而同一批代码的测试注释却写着**相反的意图**（见 §1.5）。**"设计契约"本身是自相矛盾的。**

### 1.4 缺陷 B：参考世界在生产路径下丢同义词（更严重，且此前无人发现）

> **加载 `default_world()` 后（这就是 `bootstrap.main()` 的真实路径），"砍柴/木头/树/木" 这些同义说法全部接不住 —— 而测试里是接得住的。**

**根因**：`load_resource_lexicon_from_world` 从 `world["locations"][*]["resources"]` 收集时用
`lex.setdefault(name, [name])` → 得到**单元素桶**；后两步尝试给它补别名：
- manifest `resources` 段 → 由 bat 提供，**裸启动时没有**
- `world["_resource_aliases"]` → **`default_world()` 从未声明过这个键**

于是 `active` 非空（所以不触发回退）、但**每条只有规范名自身** → 同义词全丢。

**为什么测试看不见**：全仓**没有任何测试**做过"加载 `default_world()` 之后 `compile_task`"
这件事 —— 测试都在态③（未加载）跑，走的是硬编码默认表（含同义词），于是恒绿。

**这是"测试绿但线上错"的典型**：三态退化 + 参考世界少声明一个键，两个问题叠加把症状藏住了。

> 补充说明：缺陷 B **不是本次改动引入的**（`default_world()` 一直没有 `_resource_aliases`）。
> 但我在去游戏化时**主动跳过了**给 `default_world()` 补 `_resource_aliases`（当时判断"改动小、
> 测试不可见"），实际效果是**把这个活 bug 原样留在了原地**。这一条我应该在上一轮就报出来。

### 1.5 项目内部自相矛盾（同文件两个测试意图相反）

| 位置 | 原文 | 意图 |
|---|---|---|
| `tests/test_resource_lexicon.py:30`（注释） | `# 整表替换: 别游戏的"木材"不再误接（GTA 纯对话世界同理不接采集单）` | 零资源世界**不该**接单 |
| `tests/test_resource_lexicon.py:34-38` | `def test_empty_world_falls_back_to_default(): """纯对话世界(零资源) → 回退内置默认表（GTA 模式）。"""` <br> `assert compile_task("给我一根木材") is not None   # 回退默认` | 零资源世界**该**接单 |

两条断言的是**相反的行为**。而现在代码实现的是后者。

### 1.6 修它的影响面（精确到条）

**代码改动（2 处，均在 `npc/reviewer.py`）**
1. 区分态②与态③：`_ACTIVE_RESOURCE_ALIASES` 已有 `None` 语义 → 把 `active if active else None` 改为
   `active`（空 dict 即"已加载但什么也没声明"），并把两处 `... or DEFAULT_RESOURCE_ALIASES` 的回落
   收紧为"仅 `None` 时回落"。
2. 同步 `reviewer.py:59-62` 的 docstring（它现在**把缺陷 A 写成契约**）。

**`default_world()` 补 1 个声明键**（修缺陷 B）：
```python
"_resource_aliases": {"木材": ["木材","木头","柴","木","树"],
                      "浆果": ["浆果","果"], "石头": ["石头","石"]},
```

**测试改动（1 个必须改写 + 2 个必须新增）**

| 动作 | 用例 | 说明 |
|---|---|---|
| 改写 | `test_resource_lexicon.py::test_empty_world_falls_back_to_default` | 断言相反 → 改为 `test_empty_world_has_empty_lexicon`：零资源世界 → `compile_task("给我一根木材") is None` |
| **新增（必需）** | `test_default_world_lexicon_keeps_aliases` | 加载 `default_world()` 后 `compile_task("去帮我砍点柴")["resource"] == "木材"` —— **没有这条，缺陷 B 会再次隐形** |
| **新增（必需）** | `test_reference_lexicon_matches_undeclared` | 态①（加载参考世界）与态③（未加载）行为等价 —— 钉住"参考世界声明完整" |

**行为影响面（只有两类，都可控）**

| 场景 | 现在 | 修后 |
|---|---|---|
| 参考世界（`default_world()`）| 同义说法接不住 | **接得住**（修 bug，行为变好） |
| 纯对话游戏（零资源世界）| 误接「木材」单 | **不接**（符合三态，符合 `:30` 注释的意图） |
| 显式声明了资源的游戏世界 | 不变 | 不变 |
| 未加载世界的裸调用/测试 | 不变（态③） | 不变 |

**不挂的测试**：`test_dynamic_resource_from_world` / `test_aliases_from_world_extension_key` /
`test_manifest_resources_extra_merge`（各自声明了资源 → 态①）、`test_subagent.py:141/164/176`
（monkeypatch 掉 `get_resource_aliases`）、`test_default_lexicon_unchanged`（态③）。
**唯一会挂的就是上面那 1 个需要改写的用例。**

## 三、前端审计（Web Console）

### 3.1 必须改（唯一硬缺陷）

**`memory-journal` 返回形状前后端不符 → 「整理流水」区块恒定显示为空**

| 端 | 事实 |
|---|---|
| 后端 | `npc/server.py:925` `return records[-lim:]` —— **裸 JSON 数组**；测试锚定：`tests/test_memory_report_api.py:113` `assert r.json() == []`、`:129-131` `len(body) == 5` |
| 前端 | `src/types.ts:284-286` 定义为对象 `{ entries?: MemoryJournalEntry[] }`；`src/api/client.ts:118-121` 按对象接收；`src/components/MemoryHealth.tsx:223,259` 用 `journal?.entries ?? []` |

**后果**：`journal` 实际是数组 → `journal.entries` 命中 `Array.prototype.entries`（是个**函数**，非 null/undefined）→ `?? []` 不生效 → `entries.length === 0` 恒真 → `MemoryHealth.tsx:362-363` **永远显示"这个 NPC 没有整理流水记录。"**。不崩，但功能静默失效。

**修法二选一**：前端改成 `req<MemoryJournalEntry[]>` 并直接持有数组（**推荐**，后端有测试锚定）；或后端改成 `{"entries": [...]}`（要同步改 2 处测试）。
**附带**：`types.ts:274` 注释里的路径 `/api/npcs/{pid}/memory/journal` 是错的，真实路由是 `memory-journal`。
