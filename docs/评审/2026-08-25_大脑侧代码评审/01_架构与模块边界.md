## 二、发现（12 条）

### F1【上帝类·高风险核心】NPC 类八职合一
拆分提案（每步全量跑基线）：`llm_wiring.py`（最便宜，调用方 npc 内 3 处+subagent.py:119+server.py:824）→ `events_archive.py` → `book.py`（≈140 行，风险中）→ `talk_pipeline.py`（≈250 行，风险高）→ `memory_card.py`（save() 生产调用点 8 处，中高）。executor（R5 ≈95 行）或与 scheduler 收敛。

### F2【上帝模块·高】create_npc_server 664 行闭包工厂 + main() 同文件
提案：① events_archive 纯函数化（低）；② 端点按 APIRouter 分组保留门面（中）；③ main() 抽 bootstrap.py（低）。

### F3【架构性重复·高】同一套动词两台执行引擎
run_task（BFS 直走）与 tick 引擎（逐跳+动态权重）各实现一遍 gather/craft/deliver，已现漂移（craft 工作台硬编码只在 run_task 有）。短期至少声明 run_task「演示遗留、冻结不加功能」。

### F4【耦合·高】world.log 字符串总线一身三职
行为事实源 + 前端事件流（中文文本→正则反向解码）+ 字幕通道共用一个列表；任一方改措辞三方齐断。提案：world["_events"] 结构化双写过渡。

### F5【耦合·中高】四个进程级全局单例 vs「一实例一世界」假设不强制
SCHED / LEDGER / REGISTRY / reviewer._ACTIVE_MANIFEST 等；同进程第二实例会静默共享。导入层 DAG 成立但存在运行时环（server⇄subagent observer）。提案：WorldRuntime/AppContext 收拢；过渡期对第二实例响亮报错。

### F6【耦合·中】跨层伸手摸私有
npc._last_thinking/_talk_rules/_get_llm 被 server 直用；run_subagent 调 npc._get_llm 且直写 world["log"]。提案：thinking 入返回值、公共探测口、llm 注入参数。

### F7【层积·中】§22 封存代码仍随生产装载
import 探针、_a_semantic_block、A_SYSTEM/a_brief、features 位 "a"。提案：搬 npc/legacy_a_reviewer.py 并摘 features 位。

### F8【层积·中】协议 v1 半接线：商议队列设计了没人消费
pop_discussions 生产零调用（仅测试）；实际消费在 task_done 手工拼字幕。「NPC 先主动提起」从未接进 talk。提案：talk 前置钩子或删 API 承认未实现。

### F9【重复·中】三道门序列复制粘贴两份
规则接单与 B2 路径几乎逐行相同；book() 开关双分支重复三连赋值。铁律执行点不应有两份拷贝。提案：guarded_book 单入口合流。

### F10【层积·低中】补丁式痕迹集合
①日期戳/§编号写进代码应迁 ADR；②函数内冗余 import（os×3、pathlib）；③GTA 方言漏进通用层（_DEFAULT_DYNAMIC_PERSONA、CONTINUOUS_VERBS 硬编码）。

### F11【性能×职责·低中】save() 全量重写整卡挂在最热路径
每条对话尾部/每次反思/每个转换事件都 O(整卡) 序列化（ali 卡 1.89MB）。随 memory_card.py 收拢做增量/防抖。

### F12【配置·低】开关读取双轨制、15+ 环境变量散装
根 config.py 与 npc/ 完全脱节；判关语义两种流派。提案：统一旗标读取器（后续所有拆分的地基）。

## 三、总评

分层骨架健康：三角色、安检门、账本、调度队列边界清晰，无导入环。债集中在 NPC 类四种变更理由合一（F1/F3/F9）与 create_npc_server 闭包（F2/F8）。682 测试基线支持渐进重构，无需大爆炸。
