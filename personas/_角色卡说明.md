# 角色卡填写说明

> **一张角色卡 = 一个 NPC = `personas/{id}.json` 一个文件**。加一个文件就多一个 NPC；
> 改完存盘即生效，不用重启服务器。控制台「角色卡」页也能直接编辑同一份文件。
>
> - 空白模板：`personas/_模板.json` —— 复制一份 → 改名成你的 id（如 `bella_goth.json`）→ 把每个字段里的【…】文字换成你的内容。
> - 以 `_` 开头的文件（模板、本说明）**不算 NPC**，不会被角色列表/关系网当成角色，可以放心放在这里。

## 字段一览

| 字段 | 中文名 | 必填 | 怎么填 |
|---|---|---|---|
| `id` | 编号 | ✅ | 本文件的名字（不含 `.json`），只能小写英文/数字/下划线，如 `bella_goth`。必须与文件名一致 |
| `name` | 显示名 | ✅ | 游戏里怎么称呼它，如 `哥特贝拉` |
| `identity` | 身份 | 推荐 | 它是谁、干什么的、处在什么处境。一两句话 |
| `personality` | 性格 | 推荐 | 脾气秉性、在意什么、怕什么 |
| `speech_style` | 说话风格 | 推荐 | 长短句、口癖、语气（"短句不废话"比"很酷"管用） |
| `voice_samples` | 语气锚点 | 推荐 | 写 2~3 句**它真会说的话**，让模型抓住语气 |
| `taboos` | 忌讳 | 可选 | 它绝不会做的事 / 不会说的话 |
| `rules.replies` | 关键词兜底 | 可选 | 没接上大模型时：玩家话里出现该关键词 → 直接回这句 |
| `rules.fallback` | 万能兜底 | 可选 | 没接上大模型且没命中关键词时说的话 |
| `entity_synonyms` | 同义词族 | 可选 | 同一个东西的多种叫法归到一个标准词（供**记忆检索**用）；**标准词本身也要写进它的列表**，如 `"玫瑰": ["玫瑰", "花儿", "花"]` |
| `voice` | 音色 | 可选 | TTS 音色名（要装 `edge-tts` 才有声），留空用默认 |
| `relations` | 关系网 | 可选 | 只画控制台关系图（制作者手填），不影响对话 |

## 最小可用示例（复制就能改）

```json
{
  "id": "bella_goth",
  "name": "哥特贝拉",
  "identity": "哥特家的女主人，柳溪镇人人都认识的社交名媛。",
  "personality": "外表优雅得体，其实好奇心重，爱打听别人的事。",
  "speech_style": "礼貌但带点高高在上，喜欢用反问句。",
  "voice_samples": [
    "亲爱的，柳溪镇没有我不知道的事。",
    "别急着走呀，你还没告诉我今天去哪儿了呢。"
  ],
  "taboos": ["绝不当众失态"],
  "rules": {
    "replies": { "玫瑰": "我家的玫瑰今年开得可好了。" },
    "fallback": "嗯……让我想想。"
  },
  "entity_synonyms": { "玫瑰": ["玫瑰", "花儿", "花"] },
  "voice": "",
  "relations": [{ "who": "cang", "how": "老邻居", "weight": 0.5 }]
}
```

## 常见坑

1. **`id` 与文件名必须一致**（`bella_goth.json` 里就写 `"id": "bella_goth"`），不一致控制台会拒绝保存。
2. **必须是合法 JSON**：不能写 `//` 注释、末尾不能多逗号、键名要用英文双引号。
3. `rules` 是**降级兜底**，不是主台词 —— 平时台词由大模型按角色卡临场生成；只有没接上大模型时才用它。
4. `voice_samples` 优先写"原话"，不要写性格概括 —— 它是给模型的**语气锚点**。
5. `entity_synonyms` 不填也能跑；填了以后 NPC 更容易"想起"聊过的事。写法上有一条容易漏：
   **标准词本身也要作为别名写进它自己的列表**（`"玫瑰": ["玫瑰", "花儿", "花"]`）—— 检索只拿列表里的词去匹配，
   标准词漏了就等于这个词自己永远不命中。
6. **游戏那边怎么认人**是另一回事：mod 侧有一份配置（市民名 → npc_id 映射），不在这张角色卡里。
